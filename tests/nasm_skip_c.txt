# tests/nasm_skip_c.txt -- the C PORT's skip list for the nasm differential gate.
#
# ONE `NAME<2+ spaces>reason` PER LINE.  This is the C leg's OWN list, separate from
# tests/nasm_skip.txt, which lists the REFERENCE leg's blind spots (P0).  A name is here
# only because the C binary, run against the native fixture, EITHER
#
#   (a) stops with `unimplemented: <symbol>` -- an opcode whose C definition does not
#       exist yet (the emitter classifies it and names it; see gen/interpreter_c.js and
#       src/cpu/interpreter_gen.c).  Nearly all of these are M1b's 0F table
#       (MMX/SSE 0F 6F/7F/6E/7E/28, setcc, bt/bts/btr/btc, cmpxchg...) and M1b's FPU (the
#       D8..DF group).  THE REASON IS THE SYMBOL THE BINARY PRINTED, not a guess: this
#       file was generated from a run made with --skip-list /dev/null.  Adding a
#       definition to src/cpu/instructions_0f.c or fpu.c (M1b) regenerates the
#       dispatcher and takes the test off this list -- that is the point of its shape.
#
#   (b) diverges from the native (hardware) fixture for a reason that is a property of
#       the EMULATOR'S MODEL rather than a defect: v86 maps everything below 0xA0000 to
#       plain RAM, so a store to address 0 succeeds where the host MMU faults.  The
#       reference has exactly the same gap (P0's class B, results/p0-oracle-scaffold.md
#       section 7) and the port reproduces it faithfully.
#
#
# REGENERATED by M1b-2 (HANDOFF=v86c) from a `--skip-list /dev/null` run: the 58 MMX/SSE
# entries M1a-4's list carried are GONE -- every symbol they named is now defined, so those
# tests run and pass.  What is left is the class-B set and the jump assert, all of which
# the JS reference reproduces (MEASURED, see the reasons).
# A skip is NOT a pass: every entry is printed with its reason by `make nasm`, the counts
# are reported, and results/m1a4-emitter-runloop.md carries the full table.  The gate's
# ability to FAIL is demonstrated by the negative control in that report.
jump  src/cpu/cpu.c:83: assert(!in_mapped_range(phys_addr)) failed -- the fixture's jump reaches a region v86's flat 2 MiB memory model maps differently (P0 class B, the same model gap as pop_esp); unchanged since M1a-4
maskmovdqu  P0 class B: the native fixture expects a #GP at 0x80055 where the port writes below the stack, but address 0 is plain guest RAM in v86's flat model, so neither the reference nor the port faults. MEASURED: the JS reference leg gives the port's exact actual eip/exception (0x80078 / None)
maskmovq  P0 class B: same as maskmovdqu (fixture #GP at 0x8004f, port and JS reference both report eip 0x8006e / no exception)
pop_esp  the native fixture expects a #GP at 0x80023 from a store to address 0; address 0 is plain guest RAM in v86's flat 2 MiB memory model, so neither the reference nor the port takes a fault (P0 class B) and the C leg halts instead -- the same emulator-model gap, not a port defect
pop_esp2  same as pop_esp: the fixture's SIGSEGV comes from the host MMU writing to address 0, which the emulator does not model (P0 class B)
