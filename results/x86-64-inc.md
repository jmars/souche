# x86-64: `inc %eax` in long mode was 64-bit — the SDM default-64 group read off the OPCODE

**Status: A MEASURED PORT DEFECT, ONE FIX, ONE ARM (fails before / passes after), and the guest now
runs PAST `setup_per_cpu_areas` with the `percpu: cpu 0 has no node -1` warning gone. Full battery by
exit code; no pinned number or byte moved.** Claims tagged MEASURED / READ / INTERPRETATION.

## 1. The measurement selected reading (a): the instruction, not the return path (MEASURED)

    BREAK 0xffffffff8309da5d (the `inc %eax`)   rax=0xffffffff  (hits 8192)
    BREAK 0xffffffff8309daaf (the `jne` target) hits=8192
    BREAK 0xffffffff8309da5f (after the inc)    rax=0x100000000

`inc %eax` with `eax = 0xffffffff` must write EAX (zero-extending into RAX: `rax = 0`) and set ZF. The
port produced **`rax = 0x100000000`** and ZF clear, so the `jne` that implements
`if (early_cpu_to_node(i) != NUMA_NO_NODE) continue` was taken for all 8192 cpus. Reading (b) — the
return value lost through the `jmp` thunk — is **refuted**: the value at the `inc` is right, the
instruction's own result is wrong.

## 2. Root cause (READ, `src/cpu/long_mode_gen.c:48-70`, `src/cpu/modrm.c:652-668`)

`long_mode_default64()` answers **per OPCODE**, and `case 0xFF: return true`. But in the SDM's
default-64 group only **FF /2 (call), /4 (jmp) and /6 (push)** default to a 64-bit operand size in a
64-bit code segment; **FF /0 (inc) and FF /1 (dec) keep the 32-bit default** and are 64-bit only under
REX.W. The dispatch key cannot see the modrm, so every `0xFF` in long mode without REX.W reached
`instr64_FF_0_*`/`instr64_FF_1_*` — `inc64` on a 32-bit operand: the 64-bit sum, and ZF/SF/PF computed at
width **64**, where `0x100000000` has bit 32 set and is therefore "not zero".

## 3. The fix (one decision, four bodies: `src/cpu/instructions_64.c:739-783`)

`instr64_FF_0_{reg,mem}` and `instr64_FF_1_{reg,mem}` now branch on `PREFIX_REX_W`: without it they do the
32-bit operation (`inc32`/`dec32` through `read_reg32`/`write_reg32`, or `safe_read32_addr`/
`safe_write32_addr` for the memory forms); with it they keep `inc64`/`dec64` unchanged. The group's other
members (`/2`, `/4`, `/6`) are untouched — they really are default-64.

**`dec` is the same class and is fixed by the same change; `neg` and `not` are NOT** — `0xF7` is not in
`long_mode_default64`, so those two were already dispatching at 32 bits (READ).

## 4. The arm (MEASURED: fails before, passes after)

`src/cpu/m1c_selftest.c`'s `test_long_mode_ff_inc_dec_are_32bit_without_rexw`, registered in `main`:

    against the PRE-FIX bodies:   FAIL read_reg64(EAX) == 0ull (got 0x100000000, want 0x0)
                                  FAIL getzf()
    against the FIXED bodies:     PASS FF /0 and FF /1 in long mode are 32-bit without REX.W …

The arm also pins `dec %eax` on the 0−1 edge and the REX.W control (`rax = 0x100000000`, ZF clear). The
**memory forms are not covered by the arm** — `safe_*_addr` needs a long-mode PAE page table this harness
does not build (it asserts CR4.PAE) — so the guest run is their coverage; stated rather than papered over.
