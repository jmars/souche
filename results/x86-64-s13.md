# X86-64-S13 — the engines: the 64-bit engine differential becomes REAL

**Unit:** `HANDOFF=v86c-x86-64-s13`, slice **S13** (the last) of `results/x86-64-plan.md` (§6's S13
row; §3.4 the cascade). S0-S12 are landed.

**The claim, one sentence:** all three engines now **run** IA-32e — the interpreter natively and the
cache engines by **delegating each long-mode batch to the interpreter** (counted) — so the **64-bit
engine differential** S5 recorded as **vacuous** is now a real instrument: **each engine agrees with
the host on all 63 cases**, and the three engines' **documents are byte-identical**, state tail
included. **What is NOT landed, and is the gap: the uop decoder's own long-mode arms and the JIT's
64-bit recipes.**

The shipped binary moved `021c0929…` (S12) to **`c332c790…`** (MEASURED) — this slice touches the
shipped path (the cache is ON by default), so every pin below is the load-bearing part of the gate.

---

## 1. What landed

**`uop_cache.c`: the long-mode DELEGATION.** S5 landed a named stop (the decoder would read
`0x40-0x4F` as INC/DEC and desynchronise silently). S13 replaces it with the plan §3.4 shape — the
**whole batch goes to the interpreter**, counted as `long_mode_batches` and printed beside the other
counters. So a 64-bit guest now **runs** on `uop` and `uopjit` (slowly, with zero caching) instead of
being refused.

**`cpu_backend.c`: all three engines declare `CPU_MODE_LONG|COMPAT`.** A capability word is about
what an engine can **run**, not how fast: before this line `uop`/`uopjit` refused the mode, which is
exactly why S5's differential was vacuous.

**`uop_cache.h`/`.c`: the counter and its print** — `long-mode batches delegated to the interpreter:
N`. Without a printed counter the claim "the cache delegates" would have no instrument, which is the
plan's own rule (a seat nobody can read is a gap).

## 2. The instrument: `tests/gate-x86-64-diff.sh` (new, 13 passed / 0 failed)

| step | what it asserts |
|---|---|
| A `corpus-{interp,uop,uopjit}` | **each engine** is `green=63 red_unimplemented=0 mismatch=0 error=0` against the **host** |
| B `identical-{case}` ×6 | the three engines' **documents are byte-identical** (`cmp`) for six cases spanning the six families — the v2 array **and** the STATE tail (efer/cr/cr3/gdtr/idtr/segments) |
| B `differential-can-fail` | **able-to-fail**: two DIFFERENT cases' documents must not compare equal |
| C `uop-delegates` | the counter is non-zero in long mode |
| C `no-long-mode-no-delegation` | **the control**: the same run **without** the flag delegates **zero** — the counter measures the mode, not the engine |
| C `jit-no-long-mode-blocks` | the JIT compiles **no** long-mode block (the ten it did compile belong to the stub's 16/32-bit phase) |

**The differential's blind spot is the corpus, and it is named**: the corpus is 63 cases over six
families; an engine that disagreed on an encoding no case contains would not be caught. That is the
plan's falsifier ("a differential mismatch that the corpus does not have a test for ⇒ corpus gap,
recorded") and it is recorded here rather than implied.

## 3. Two arms INVERTED, visibly, and one selftest arm retired

- `gate-long-mode.sh`'s **`uopjit-refuses-long-mode`** and both **`differential-vacuous-*`** steps
  asserted S5's statement (the engines refuse the mode). They now assert the opposite — the same
  probes must **run** — and the `uop-decoder-refusal` step became `uop-delegates-long-mode`
  (the counter, on a real image).
- **`uop_cache_selftest`'s S5 arm is RETIRED, and the reason is measured**: it put LMA in the sandbox
  by hand and required a named stop; with the stop replaced by a delegation the run **executes**, so
  the sandbox would need a real PML4 and IDT — a half-built one **crashed the suite** (MEASURED,
  SIGABRT then SIGKILL). The delegation's instrument is the gate's counter pair, which runs on real
  images and is the stronger proof. The function is kept (marked unused) with that reasoning in it.

## 4. NAMED GAPS — the engines' own arms

1. **The uop decoder's long-mode arms**: the decoder still reads 32-bit rules; every long-mode batch
   is delegated. Landing the arms means REX in `dec_prefix`, the three-valued key, a **third modrm
   extractor** (RIP-relative, SIB-64), the descriptor tables generated from the overlay, and the
   executors calling `instr64_*` — i.e. S5-S10 again inside `uop_cache.c`. The differential is the
   gate that would judge it, and it is now real.
2. **The JIT's 64-bit recipes**: zero coverage, by construction (`instr64_*` has no recipe and falls
   back to `uop_exec_uop`) — which is now **measurable** rather than asserted: the delegation makes
   the fallback path the one that runs, and `jit-no-long-mode-blocks` pins it.
3. **The 64-bit engine differential is only as wide as the corpus** (§2).

**The ISA layer's proof: the whole 63-case corpus is green against the host** — `green=63
red_unimplemented=0 mismatch=0 error=0` — on **all three engines**, and the three documents are
byte-identical.

**The named gaps, in the order the next session should take them:**

1. **The 64-bit IDT gate decode and the 64-bit interrupt frame** (S11/S12's stop): the amd64 kernel
   reaches `eip=0x100208 cs=0x10 cr0=0x80050033 cr3=0x4f76000` and stops at
   `call_interrupt_vector: invalid gate type`. **This is the first thing to pick up**: the hypothesis
   (S12 §3.3) is that the 64-bit descriptor's **offset composition** is the suspect, and the STATE
   tail already prints `idtr` — so the first step is to read the descriptor the kernel wrote.
2. **The 64-bit GDT/TSS/IST load paths** and **SYSCALL/SYSRET** (S11's gaps), then **SWAPGS** (needs an
   authored dispatch arm: `0F 01 /5` has no entry in the reference's table).
3. **The amd64 initramfs and the userspace milestone** (S12's gap), with the **QEMU leg** as the
   second reference — the leg that separates a port defect from a kernel requirement.
4. **The engines' own arms** (§4): the uop decoder's long mode, then the JIT's recipes.
