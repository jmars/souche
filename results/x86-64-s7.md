# X86-64-S7 — control flow and stack at 64 bits

**Unit:** `HANDOFF=v86c-x86-64-s7`, slice **S7** of `results/x86-64-plan.md` (§6's S7 row: "jcc/
jmp/call/ret/push/pop/`mov imm64`/`lea`/`movsxd`/`movzx`/`movsx`/`cmov`/`setcc`/`xchg`"; corpus
family 3; rung coder). S0-S6 are landed; S8-S13 are untouched.

**The claim, one sentence:** all twelve family-3 cases are **green against the host** — including
the far-transfer spine `call rel32`/`ret` (an **eight**-byte return address through a 64-bit RSP)
and the indirect `jmp r/m64` — and the far-transfer seats S5 left by name (ret, call rel32, jmp
rel32, pop r/m, the 0xFF group) are now **bodies with the case that proves each**, while the ones
no case covers stay **named stops with the reason**. The 0F escape gained its **third operand-size
arm**, so cmovcc/setcc/movzx/movsx run in 64-bit mode for the first time.

The shipped binary moved `c10c4b38…` (S6 round 2) to **`76ac9fc3…`** (MEASURED, `sha256sum
build/v86c`); every gate below ran against S7 bytes.

## 3. What landed

**`gen/x86_table64.js`**: the 0F-qualified table (`x86_table64_0f`: `0F 44/45`, `0F 94/95`,
`0F B6/B7/BE/BF`) and the base-table entries for `0x0F` itself (`entry64: "instr64_0F"`), jcc rel8
(`0x70-0x7F`), `0x63` (movsxd — which **replaces** S5 round 2's `stop64` entry, since ARPL does not
exist in 64-bit mode and the real instruction is S7's), `0x87` (xchg), `0x8D` (lea). `0xC3/0xE8/
0xE9` were already overlay entries as S5's default-64 shutter; S7 gives them bodies. `0xC2/0xCA/
0xCB/0xCF` (ret imm16, retf, iretq) **stay named stops** — no case covers them and each is a far
transfer whose 64-bit form is S11's (§6).

**`gen/interpreter_c.js`**: the 0F switch gains `case 0x2NN:` arms — the same three-valued key —
generated from the 0F overlay, **and the same no-fall-through guarantee the base switch has**:
every 0F second byte WITHOUT an overlay entry emits a named-stop `0x2NN` case. That is not
decoration: without it, `dispatch_os_index_0f` answers 2 for any `0F` instruction with `REX.W`
(e.g. `bswap`, `movd`), the key hit the 0F switch's `default: DBG_ASSERT(false)` and **aborted the
host on 10 corpus cases** (MEASURED, before this case existed).

**`src/cpu/modrm.c`/`.h`**: `dispatch_os_index_0f` — the escape's second byte under the same rule
(`REX.W → 2`, `0x66 → 0`, else 1; `is_osize_32()` again deliberately unused in long mode).

**`src/cpu/instructions_0f.c`/`.h`**: `run_instruction0f_64` — the third wrapper, reached only
through `instr64_0F`.

**`src/cpu/instructions_64.c`/`.h`**: 45 new bodies — `instr64_0F` (the escape), sixteen jcc
rel8 one-liners over the port's own `test_*` predicates, `call rel32`, `ret`, `jmp rel32`,
`0xFF /4` (jmp r/m64), `0xFF /6` (push r/m64), `lea`, `movsxd`, `xchg`, and the eight 0F bodies
(cmov×2, setcc×2, movzx/movsx×4). Also: `instr64_EB` (jmp rel8) **lost** the `after_block_boundary`
call S5 added — the reference's table marks jmp rel8 `block_boundary:1,
no_block_boundary_in_interpreted:1`, which the emitter reads as "no postfix in the interpreter";
S5's version called it anyway (harmless — a batch end is invisible to the compared state — but a
divergence), and the jcc bodies follow the reference instead, so the two agree.

## 4. The stack discipline, and what each body would catch

The slice's silent-wrong surface is the EIGHT-byte stack: `call` pushes eight (the 32-bit arm
pushes four — a four-byte push drifts every subsequent rsp by 4 and returns into the middle of the
pushed pair), `ret` pops eight, and the return address is the fetch cursor **after** the
displacement is consumed (which `cpu->instruction_pointer` already is when the body runs). The
case that discriminates is `ctrl-call-ret-64`: a callee that `add`s, a `ret`, and code after the
call — a four-byte push or an early return address produces a different `rax`/`rsp` than the host.

`push r/m64` (`0xFF /6`) was S5's shutter and is now a body: the same eight-byte rule, and its
source address is a 64-bit one (`[rip + disp32]`).

## 5. The 0F escape's third arm, and why the emitter change is safe

`instr64_0F` reads the second byte and keys it with `dispatch_os_index_0f`; the generated 0F switch
gains `case 0x2NN:` arms **only** for the overlay's 0F entries, and a named-stop `0x2NN` case for
**every** other second byte. The 16/32-bit 0F arms are untouched, and outside long mode
`dispatch_os_index_0f` is exactly the old `is_osize_32() ? 1 : 0`, so no 32-bit path can reach a
0x2NN case. The 0F sub-opcodes S7 does not land (0F 0D/1E prefetch, 0F 1F nop — which need no arm
since they are `e:1` NOPs in the 32-bit table and would run the 32-bit arm correctly — plus every
SSE/S8/S9 encoding) stop by name.

## 6. What this slice does NOT cover, named rather than implied

- **`jcc rel32` (0F 80-8F)**: no case uses the rel32 form (gas picks rel8 within range), so there
  is no arm — a long-jump case is the missing instrument.
- **`jcxz`/`loop`/`loope`/`loopne` (0xE0-E3)**: `0xE3` (JRCXZ) was S5 round 2's `stop64` entry and
  **still is** — S7's `stop64` for 0x63 was replaced by the real body, but 0xE3's remains a named
  stop because no case uses it and its counter rule (RCX, and the 0x67 address-size forms) is
  uninstrumented.
- **`ret imm16` (0xC2), `retf` (0xCA/0xCB), `iretq` (0xCF)**: named stops (S11's far transfers).
- **`call r/m64` (0xFF /2), `callf` (/3), `jmpf` (/5)**: named stops — far transfers, S11's.
- **`xchg r/m64, r64` with a memory operand**: `instr64_87_mem` exists but NO case covers the
  memory form (the corpus uses the register form), so it is **unproven** — stated here because the
  body exists and a reader should not mistake existence for verification.
- **`cmovcc`/`setcc` for the other fourteen conditions**: named stops (`0F 46-4F`, `0F 96-9F`);
  only `e`/`ne` are instrumented.
- **`enter`/`leave` (0xC8/0xC9)**: not in the overlay; they stop by name (no case).
