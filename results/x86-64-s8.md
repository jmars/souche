# X86-64-S8 — MUL / DIV / SHIFTS at 64 bits

**Unit:** `HANDOFF=v86c-x86-64-s8`, slice **S8** of `results/x86-64-plan.md` (§6's S8 row:
"mul/imul/div/idiv — the 128-bit results, the count masks, the `OF` cases"; corpus family 4; §2.1.5's
rule that only SDM-**defined** outcomes may enter the corpus). S0-S7 are landed; S9-S13 untouched.

**The claim, one sentence:** the 64-bit `MUL`/`IMUL`/`DIV`/`IDIV` now produce the full **RDX:RAX
128-bit** result through `unsigned __int128`/`__int128` with the divide-error condition intact, the
shift/rotate group works at 64 bits with the **0x3F** count mask and the count-0 flag rule, and
**all eleven family-4 cases are green against the host** — with every undefined flag bit excluded
by mask and named, rather than compared by luck.

The shipped binary moved `2bd29635…` (S7 round 2) to **`fd1b4973…`** (MEASURED, `sha256sum
build/v86c`); every gate below ran against S8 bytes.

## 4. The defined-only rule, applied to the corpus (not just stated)

The corpus may contain only outcomes the SDM **states** (§2.1.5), and every family-4 case ends in an
operation with *some* undefined flag. Each case therefore now stores its flags word **masked to the
bits its own last operation defines**, and ends with a flag-**defining** instruction that touches no
register, because the document's dedicated `rflags` element is compared with `MASK_ARITH`
unconditionally:

| operation | defined flags | mask used |
|---|---|---|
| `MUL`/`IMUL` | CF, OF | `0x801` |
| `DIV`/`IDIV` | **none** (all six undefined) | no store — the result is the assertion |
| `BSF`/`BSR` | ZF | `0x40` |
| `BT`/`BTS`/`BTR`/`BTC` | CF | `0x1` |
| `ROL`/`ROR` | CF (and OF at count 1) | `0x1` |
| `SHL`/`SHR`/`SAR` | CF, PF, ZF, SF (AF undefined; OF only at count 1) | `0xC5` |
| `SHLD`/`SHRD` (count 1) | CF, PF, ZF, SF, OF (AF undefined) | `0x8C5` |

The normalizer is `cmp rax, rax` — it defines all six flags and writes no register. **The undefined
bits are therefore EXCLUDED BY RULE and named here**, which is what S6's round-2 AF finding asked
for at the element level; the alternative (comparing them and being green because this host happens
to agree) is exactly what that finding rejected.

## 5. The silent-wrong surfaces, named whether or not they bit

1. **The 128-bit product's high half** — a 64×64 multiply done in 64 bits drops RDX. **It bit
   nothing** (my first implementation used `__int128`), and it is **instrumented**: a mutant that
   writes the low half into both RAX and RDX turns `mul-128` red (MEASURED, §7).
2. **The sign extension of IMUL's operands** — a zero-extended 32-bit operand gives the wrong
   product for negatives. Instrumented by `imul-one` (`-1 × 0x100000000`) and `imul-two-three`
   (`imul rdx, rcx, -1`).
3. **The divide-error condition and its priority** — `#DE` when the divisor is 0 **or** the quotient
   does not fit, and it must fire **before** any register is written. `div64_without_fault` /
   `idiv64_without_fault` return false before writing; `alu-div-zero` (S6's `#DE` case) now
   **reaches its SIGFPE** through the 64-bit DIV (the gate asserts it), and `idiv64`'s bound is
   `INT64_MAX`/`INT64_MIN` — the corner `INT64_MIN / -1`, which `__int128` holds so the check is the
   only guard.
4. **The count mask: 0x3F, not 0x1F** — every shift body masks at the call site
   (`read_reg8(CL) & 63`), mirroring the 32-bit bodies' `& 31`. Instrumented by
   `shl-shr-sar-64` (`cl = 40`).
5. **The flags at count 0** — every wrapper returns early on `count == 0`, leaving all flags alone.
   Instrumented by `shifts-imm64`'s `shl rcx, 0`.

**One defect this slice found in its own first version, worth carrying**: `bsf_bsr_flags` (and
`bt64`, `rol64`, `ror64`) originally wrote the flag value **and marked the bit stale**, so the getter
recomputed it from the *previous* operation's lazy operands — a **wrong** answer, not an undefined
one. MEASURED: the port reported ZF=1 after a `bsr` whose source was `0x8000000000000000` (the stale
operands were the prologue's `xor eax,eax`), against the host's ZF=0. The fix is to **materialize**
(`flags_changed &= ~BIT`) rather than mark stale — the mirror image of the `flags_add` family, which
marks stale and lets the getters compute.

## 6. What this slice does NOT cover, named rather than implied

- **`RCL`/`RCR`** (`0xD1`/`0xD3`/`0xC1` `/2`,`/3`): named stops — no case, and their carry-in rule is
  its own instrument.
- **The 8-bit and 16-bit MUL/DIV** (`0xF6`, and `0xF7` under `0x66`): the 66 forms are covered by
  S7 round 2's `narrow64` stop; `0xF6` has no 64-bit meaning.
- **`BSWAP`'s other seven register encodings** exist as bodies (`0F C9..CF`), and the corpus drives
  only `0F CA`; the other seven are **unproven** (the same body with a different register index, so
  the risk is small — stated, not assumed).
- **`BT`/`BTS`/`BTR`/`BTC` with a MEMORY operand**: the bodies now implement the SDM's
  byte-granular bit-string scheme (round 2 §9.2 fixed them from a wrong-by-construction
  `bit & 63`), but **no case grades them** — un-instrumented, stated as such.
- **THE 30 `_mem` BODIES WITHOUT CASES** (round 2, NTH 6): every family-4 case drives register
  forms, so `instr64_{69,6B,F7_4..7,0FAF,0FA5,0FAD,0FBC,0FBD,0FBA_4..7}_mem`, `C1_1`, `D1_5`,
  `D1_7` and the rest are bodies with no instrument.  The memory forms reuse the same wrappers and
  the same 64-bit address path the mov family exercises, so the risk is bounded — but "bounded" is
  not "verified", and this line is the honest count.
- **The register forms `0F A3/AB/B3/BB`** (bt/bts/btr/btc r/m, r): named stops — no case.
- **`SHLD`/`SHRD` by imm8** (`0F A4`/`AC`) and by a count > 63: named stops / masked respectively.
- **`DIV`'s partial effects on a faulting #DE** are the SDM's "undefined destination" corner — out of
  the corpus by rule, and the port writes nothing before the check.

## 9. Round 2 — one blocker, four should-fix, two nice-to-have, all fixed

The review found **one blocker** (a lazy-flags clobber in the rotates, the same shape as this
slice's own `bsf` defect), **four should-fix** (a wrong-by-construction memory form, two
un-instrumented paths the report claimed, a `#DE` branch with no case, an un-compared defined-`OF`
rule) and **two nice-to-have** (report counts, an inherited UB). All fixed; the binary moved
`fd1b4973…` → **`28ed5bd6…`** (MEASURED) and every gate below ran against round-2 bytes.

### 9.1 BLOCKER 1 — `rol64`/`ror64` clobbered the lazy operands the *unaffected* flags read

Both called `set_last_result(result, OPSIZE_64)`, and the `sub`/`add`/`mul` families mark ZF/SF/PF/
AF **stale** with `last_result` set — so the rotate overwrote the operands those getters recompute
from, and a `jz` after `sub; rol` read ZF from the **rotated** value. The SDM says ROL/ROR leave
those flags **unaffected**. **FIX: delete the call** (the 32-bit mirrors `rol32`/`ror32` never made
it, which is why they are right and this was not).

**The case, and the trap in writing it.** `muldiv-rol-preserves-flags` (new): a `sub` that zeroes a
register (ZF=1, PF=1, SF=0), then a rotate **of a different register whose result is 3**, then a
masked snapshot. **MEASURED asymmetry:** with the clobbering mutant the case is `mismatch=1`; with
the fix it is green. **And the first version of the case could not fail**: it rotated the
just-zeroed register, so the mutant recomputed ZF from a result of 0 and agreed with the fix —
the same "an arm that cannot fail" lesson this lane has now recorded three times.

### 9.2 SHOULD-FIX 2 — the `BT` **memory** forms were wrong by construction, not "unproven"

The SDM does **not** mask a memory bit base: the byte is `addr + (bit >> 3)` and the bit inside it
is `bit & 7` (the 32-bit `bt_mem` scheme). Round 1 masked `bit & 63` for both forms, and
`read_imm8()` returns 0..255, so a guest-reachable imm8 in [64,255] selected the **wrong bit** and,
for BTS/BTR/BTC, **wrote the wrong byte**. **FIX:** the four `_mem` bodies now use the byte-granular
scheme with a shared `bt_mem_flags` helper; the register forms keep the 0x3F mask (correct there).
The report's §6 "unproven" line was wrong in the unsafe direction and is corrected in §6.

### 9.3 SHOULD-FIX 3 — two paths the report claimed and nothing drove

**MEASURED:** no corpus image contained `48 69`, so the **imm32 three-operand IMUL** — a named
surface — was un-instrumented; and the `rol-ror` row claimed `C1_{0,1}` while only `C1 /0` was
encoded. **FIX:** `imul rdi, rcx, 0x12345678` added to `imul-two-three`; `ror rdx, 3` (and
`rol rsi, 1`) added to `rol-ror-64`.

### 9.4 SHOULD-FIX 4 — the `#DE` quotient-overflow branch had no case

Only `divisor == 0` was driven, so a mutant with the **range check deleted** stayed green.
**FIX:** `muldiv-idiv-overflow` (new, a `fault="DE"` case): `RAX = INT64_MIN`, `RDX = -1`,
`divisor = -1` — the quotient does not fit 64 bits and the divisor is not zero, so it isolates the
bound. **MEASURED asymmetry:** deleting the check turns the case `mismatch=1`; with it, green.

### 9.5 SHOULD-FIX 5 — the defined `OF`-at-count-1 rule was un-compared

Every shift/rotate case's **last** op had count != 1, so the masks (`0xC5`/`0x1`) legitimately
dropped OF even though each case contains count-1 ops. **FIX:** a count-1 op followed by a
`0x8C5` snapshot in `shl-shr-sar-64`, `shifts-imm64` and `rol-ror-64` — the same pattern `SHLD`/
`SHRD` already had. The formulas were right; the **instrument** was missing.

### 9.6 NICE-TO-HAVE 6/7 — the report's counts, and an inherited UB

The body count is **68**, not the 60 the report claimed (corrected in §2), and §6 now names the
**30 `_mem` bodies without cases** — including all four `BT` memory forms (fixed in §9.2 but still
un-instrumented by a case), `69`'s memory form, `C1_1`, `D1_5`, `D1_7` — and states that the
`flags.c`/`flags.h` diff the brief expected does not exist in this slice. `idiv64`'s
`(__int128)target_high << 64` shifted a negative value into the sign bit — **C UB of exactly the
class `idiv32`'s own comment says it exists to avoid** — and is now built in `unsigned __int128`
and cast once.
