**Unit:** `HANDOFF=v86c-x86-64`, slices **S1** and **S2** of `results/x86-64-plan.md` (§4 = the

(`results/x86-64-s0.md`); S3-S13 are untouched.

**The claims, one sentence each.**

- **S1:** the register file and the lazy-flag operands are 64 bits wide, **and nothing 32-bit
  reads the high half** — proved by the whole existing battery being unmoved (transcript
  `8bb8eca5…`, determinism 4,000,096,757, bench 200,095,214, nasm 118/118) **plus a new poison
  probe** that seeds every widened field's upper half with `0xA5A5A5A5` and requires a

  and `load_pdpte()` reads a PML4 as a PDPT and a 3-level walk runs over 4-level tables, silently)

## 2. S1 — the register file and the flags at 64 bits, INERT

### 2.1 What landed, exactly as §4 writes it

| field | before | after | why it is a WIDEN and not a parallel field |
|---|---|---|---|
| `reg32[8]` | `int32_t` | **`reg64[8]`, `uint64_t`, RENAMED** | a field named `reg32` holding 64 bits is a comment that lies |
| `dreg[8]` | `int32_t` | `int64_t` | DR0-DR7 are 64-bit in long mode; the moves stay 32-bit, zero-extended |
| `last_op1`, `last_result` | `int32_t` | `int64_t` | `2u << 64` is UB, so `OPSIZE_64` needs a widened core, not a bigger number |
| `OPSIZE_*` | 7/15/31 | + **`OPSIZE_64 = 63`** | a bit position, so the getters' `>> last_op_size & 1` is the whole width rule |
| `state_flags` masks | 4 bits | + **`CACHED_MASK_LONG`** | defined and in `CACHED_MASK_ALL`, **not set**: nothing enters long mode yet |

`write_reg32` **zeroes** the high half (x86-64's own rule for a 32-bit destination), `read_reg32`
returns the low half as an `int32_t`, and the JIT's spill/reload pair was changed to agree — 8-byte
stores of a zero-extended host register.  That matters because the two engines' state is compared
byte for byte; see §2.2.

The byte map moved with the element size (`cpu_state.c`):

```
get_reg8_index(i)  = (i & 3) * 8 + (i >> 2 & 1)   -- AL/CL/DL/BL at bytes 0,8,16,24 and
                                                     AH/CH/DH/BH at 1,9,17,25
read_reg16(i)/write_reg16(i) : u16 index i << 2   -- was i << 1
```

The old formula indexes a flat 4-byte layout; applied to 8-byte slots it puts `AH` on the fourth
slot's high byte — the shape of the bug the JIT's own register map hit once
(`jit_codegen.c:198-201`, "a 16 KiB serial flood rather than a wrong digit").  §4's gate is the
existing battery, and the existing suite already pinned byte registers: MEASURED, restoring the old
formula fails **14** checks in `cpu_selftest`, five of them pre-existing (`:222`, `:225`, `:230`,
`:5375`, `:5417`).

### 2.2 The one design fork this slice forced: the lazy operands' CANONICAL FORM

The first build after the widening **failed `jit_codegen_selftest` with 40 differences** (MEASURED),
every one of them a negative `int32_t` that the C path had *sign*-extended into `last_op1`/
`last_result` and the JIT's 32-bit stores had left alone — the suite does a whole-`cpu_state_t`
`memcmp` between the compiled and interpreted arms (`jit_codegen_selftest.c:707`).  That is the
"two engines must not disagree about the state" contract, so the fix is not to relax the comparison.

**Decision: the lazy operands have a canonical storage form — the value masked to its operand width,
i.e. zero-extended** (`flags.h`'s `last_value`/`set_last_result`).  Consequences:

- the six flag cores mask both operands (`cpu->last_op1 = last_value(dest_operand, op_size)`), and
  every one of `arith.c`'s 36 hand-written stores now goes through `set_last_result` — the int32
  ones were the non-canonical half;
- the JIT stores 8 bytes (`jx64_mov_m64_r64`, 9 sites) of a host register whose upper half is zero
  by construction (every write to a `jitcg_greg[]` is a 32-bit operation), which is exactly
  `write_reg32`'s form;
- **no flag changes value**, and that is an argument rather than a hope: every getter examines bits
  at or below `last_op_size` (`getzf`'s `(~r & (r-1)) >> k & 1` depends only on whether bits 0..k
  are all zero), and `getcf` masks both operands itself — which is the port of the `(uint32_t)`
  casts the 32-bit getter carried, kept because they are what made the comparison happen in the
  operand's width.  The 16/32-bit behaviour is unchanged **iff** those casts survive; they do.

`getcf`'s upstream `dbg_assert!` ("a carry into the flags from beyond the operand is a porting
bug") is ported **exactly**: the low 32 bits must fit the width.  Bits 32-63 are deliberately not
examined — a 32-bit setter never wrote them, and requiring them to be zero would make the poison
probe impossible to run.

### 2.3 THE POISON PROBE, and what it can and cannot show

`--poison` seeds, **after** the boot state is established and **before** the first guest
instruction: `reg64[0..7] |= 0xA5A5A5A5A5A5A5A5`, `dreg[0..7] |= …`, `last_op1 = last_result = the
same value`.  `make poison-probe` runs the M0 image twice and requires a byte-identical transcript:

```
poison-probe: the widened fields' high halves do not reach the M0 transcript
              (8bb8eca53f5c5ccb == 8bb8eca53f5c5ccb)     [MEASURED, rc 0]
```

**Its reach, stated so its silence is not read as a proof** (and printed in `main.c`'s comment):

- `reg64[]` has **eight** slots until the high registers arrive with the 64-bit model itself
  (plan S5), so **there is no R8-R15 to seed** — the brief's "and R8-R15" has no object in this
  slice.  The formula is applied to all eight slots that exist;
- for `last_op1`/`last_result` the seed is inert **by construction** while `flags_changed` is clear
  (every getter recomputes them from the operation that set the bit), so what the run exercises
  there is only that the seed itself does not move the machine;
- **a probe that poisons both operands identically cannot fail on the interesting mutant.**  This
  was MEASURED, not reasoned: the first version of the selftest's poison arm OR'd the *same* high
  half into both operands and **passed against a `getcf` with its width mask removed** — with equal
  high halves an unmasked 64-bit comparison still ranks the low halves correctly.  The arm now runs
  two patterns, the second giving the two operands' high halves **different** values, and the
  mask-removal mutant then fails **6** checks, all of them CF (MEASURED).

So the flag cores' high-half discipline is pinned where it can actually fail: `cpu_selftest.c`'s
`test_widened_flags`, which computes the six getters, poisons a live lazy flag word two ways, and
requires the same six answers.

## 3. S2 — the mode predicate and the refusals

### 3.1 The mode predicate

`cpu_mode_of` gained its IA-32e arm (plan Appendix A): **`EFER.LMA` ⇒ `CPU_MODE_LONG`**, before the
PE test.  `EFER_LME`/`EFER_LMA`/`EFER_SCE` are defined with the SDM's bit positions (0/8/10) — the
whole reason `LME` was dead data is that only `EFER_NXE` existed (plan finding 5).

**The named gap:** Appendix A splits IA-32e into "long (64-bit)" and "long (compat)" by **CS.L**,
which is a *descriptor* bit this tree does not decode yet (it arrives with the far-transfer work).
So the predicate answers `CPU_MODE_LONG` for every IA-32e machine and `CPU_MODE_COMPAT` is
unreachable.  That is conservative for the capability check, which is what the predicate feeds:
compat and 64-bit mode need the same backend capability.  The arms that exist are pinned including
the LMA one; the arm that cannot exist is named here.

### 3.2 C5, and the THREE doors it had (the plan names two)

C5's defect is that entering IA-32e reaches `load_pdpte()`, which reads a PML4 as a PDPT.  Three
writes can begin that transition, and all three now call one helper,
`cpu_backend_refuse_long_mode(what)`, which records the machine's **named stop** through the same
`unimplemented_instruction` channel the dispatcher's mode refusal uses, and returns "do not commit":

| write | condition | effect |
|---|---|---|
| `WRMSR` of `EFER` | the value carries `LME` | refused, `EFER` **not written** (not even the other bits in the same write) |
| `MOV CR0` | `PG` 0→1 while `LME` and `CR4.PAE` | refused, `CR0` **not written**, and the refusal is **before** the `load_pdpte` validation |
| `MOV CR4` | `PAE` 0→1 while `PG` and `LME` | refused, `CR4` **not written** |

The third is a deliberate extension of the plan's two (`instructions_0f.c`'s `MOV CR4` arm calls
`load_pdpte` too, `:516-519`): refusing at two of three would leave the class open the moment a
state arrives with `LME` set by another route (a checkpoint, a future backend flip).  A write that
does **not** ask for IA-32e is untouched: `EFER` keeps storing every other bit unchecked (the R5F
regression, re-pinned), and a write that **clears** `LME` is always allowed.

**The evidence that this is the defect and not a story.** With the `CR0.PG` refusal mutated out,
`cpu_selftest` reports (MEASURED): `cr0 = 0xffffffff80000011` (PG committed),
`protected_mode` set, `unimplemented_calls == 0`, and **`reg_pdpte[0..3]` overwritten with
0x0** — the sentinel replaced by the four PDPTE reads of a PML4-shaped page.  That is C5's
"3-level walk over 4-level tables" reproduced by deleting five lines.

### 3.3 CPUID: the declaration follows the capability (§3.5.1)

`CPUID.80000001h:EDX` returns **bit 29 (`lm`)** and **bit 11 (`syscall`)** only when
`cpu_backend_can(CPU_MODE_LONG)`, and `80000008h:EAX`'s **linear** width byte is 48 only then (the
**physical** byte stays 32 — the port's own bound, plan §5.1, and not a function of the backend).
No engine declares long mode yet, so today's values are the pinned reference's: `EDX = 0x0190A179`,
`EAX = 0x2020` (MEASURED in the suite).

**A deviation from the plan, stated rather than silently taken:** §3.5.1 also lists
`80000001h:EDX[26]` (`pdpe1gb`).  It is **not** declared.  That bit says "1 GiB pages", and this
port does not have them (they are S11's); gating it on *long mode being available* instead of on
*1 GiB pages working* would be exactly the false-declaration class §3.5.1 invokes the ACPI FADT
lesson for.  It goes in with the code that implements it.

**What cannot be tested yet, named:** the arm that *returns* those bits needs a backend that
declares `CPU_MODE_LONG`, and none does.  What is asserted instead is the **invariant** — bit
present ⟺ capability present, width 48 ⟺ capability present — which a false declaration breaks in
one direction and a missing declaration breaks in the other.  MEASURED: un-gating the bits fails 5
checks.

| instrument | claim it carries | the mutant that makes it FAIL (MEASURED) |

| `test_widened_flags` | the 64-bit cores, `OPSIZE_64`, and the getters' blindness to the high half | `getcf`'s width mask removed → **6 failures**, all CF, and **only** under the differing-high-halves pattern |

| `test_cpu_mode_and_refusals` (3a) | `WRMSR(EFER)` with `LME` refuses and stores nothing | refusal removed → **3 failures, rc 1** (`efer` becomes `0x901`, no stop) |
| `test_cpu_mode_and_refusals` (3b) | `CR0.PG` refuses **before the walk**, commits nothing | refusal removed → **8 failures, rc 1**, `reg_pdpte` overwritten (§3.2) |
| `test_cpu_mode_and_refusals` (3c) | `CR4.PAE` refuses, commits nothing | (same helper; the CR0 mutant does not cover it — the site is separate) |
| `test_cpu_mode_and_refusals` (4) | CPUID's declaration ⟺ the capability word | bits un-gated → **5 failures, rc 1** |

**The poison probe's falsifiability, honestly.**  It is a *negative* control: it can only move if
something reads a high half, and today nothing does — that IS S1's claim, so the probe cannot be
made to fail by a leak that does not exist.  What was shown instead: (a) the comparator is wired —
two `--poison` invocations at different instruction limits produce documents that differ at the
`"instruction_limit"` line and `cmp` exits 1 (MEASURED: `differ: byte 1807, line 77`), which proves
the two-run comparison can see a difference at all — it does not prove the SEED is observable, and
nothing in this slice can make it observable without a second reader of the high half;
(b) the two instruments that *can* fail on a high-half leak (`test_widened_flags`'s poison arm, and
`getcf`'s mask) do fail on their mutants.  So the probe is the end-to-end half of a claim that is
pinned directly next to it, which is the split S0 used for `engine-identity` versus the C suite.

### 5.2 S2 — the battery unmoved **and the refusals fire**

MEASURED on the S2 final source state, binary `d571ab0b…`: the same ten gates, all rc 0, with
`cpu_selftest` at **3846 checks / 0 failures** (S1's 3799 + 47 new), every other suite at the same
count, the transcript still `8bb8eca5…`, determinism still 4,000,096,757 both runs, bench still
200,095,214 with the inlining pins, reboot 39/39, VGA ×5 clean, PAE-1 11/0, PAE-L3 both legs clean.
Plus, inside `cpu_selftest`: the dispatcher's mode refusal fires by name and runs no batch, the
three entry writes refuse and commit nothing, and CPUID's coupling holds.

**The one existing check S2 moves, and why.** `m1c_selftest.c:1168`'s `WRMSR(EFER)` regression used
to write `0x1_FFFFFFFF` — every low bit set, `LME` (bit 8) and `LMA` (bit 10) included — and assert
the value was stored unchecked (the R5F finding: upstream's `dbg_assert!` is compiled out of the
shipped reference and the port must not abort).  With S2, a write carrying `LME` is a *named
refusal*, so that check failed (MEASURED: `efer` 0 instead of `0x1ffffffff`).  The value now keeps
every reserved bit set **except** those two, asserts the same "stored unchecked" property, and
points at the new test for the refusal.  This is a semantic change by design, not a re-pin: the
bits stopped being reserved.

### 5.3 What a per-cycle mode check is worth now (plan §3.3's premise)

S0 landed the dispatcher's refusal **inert** — "an instrument that cannot fail is not a test", and
S0 said so.  S2's `test_cpu_mode_and_refusals` puts the machine in long mode and calls
`cpu_backend_dispatch()`: `unimplemented_calls == 1`, the stop names the backend
(`"'interp' cannot run long mode"`), `interpreted_unimplemented` is set, and **`interpreted_run`
was not called**.  Together with §3.2's three refusals, the mode gate is now observable from both
ends: the machine cannot be *put* in a mode the engine cannot run by any guest-reachable write, and
if it somehow is, the next batch refuses instead of executing.

## 6. What did NOT land (so its absence is not read as a promise)

1. **The `LMA` transition.**  Nothing sets `EFER.LMA` yet: the SDM's rule (set on `CR0.PG`'s 0→1
   edge iff `LME && CR4.PAE`) belongs with the mode transition in **S5/S11**, and it cannot be
   exercised before a backend declares `CPU_MODE_LONG`.  S2 defines the bit and makes the predicate
   read it; the transition itself is a seat that would have been dead code here.
2. **`CPU_MODE_COMPAT`** — needs `CS.L` (S11, §3.1).
3. **`pdpe1gb`** — deliberately not declared (§3.3).
4. **The R8-R15 half of the poison seed** — no such field exists until S5 (§2.3).
5. **The probe is in-suite, not an image.**  The brief asks for "a probe image that sets
   `EFER.LME` then `CR0.PG`".  `tests/` is outside this unit's write scope, and the write it would
   perform is a `WRMSR` at CPL0 — the bodies themselves (`instr_0F30`, `set_cr0`, `instr_0F22`) are
   driven directly by the suite, which additionally asserts what an image could not (nothing
   committed, no PDPTE read, no batch run).  INTERPRETATION: an image would test the same five
   lines through a longer path; the plan's S2 gate ("the two refusals fire … the CPUID selftest
   shows `lm` clear") is met by the suite.
6. **The engine's `modes` word is unchanged** — no engine declares `CPU_MODE_LONG` yet (S5's flip),
   which is precisely why CPUID's declaration is clear and the refusal fires.
7. **S3-S13** — unstarted.
