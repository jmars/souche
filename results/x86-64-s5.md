# X86-64-S5 — the first long-mode vertical slice

**Unit:** `HANDOFF=v86c-x86-64-s5`, slice **S5** (split into **S5a** and **S5b**, §2) of
`results/x86-64-plan.md` (§3.6 = where the 64-bit decoder lives and why, §5.1 = the physical
bound, §5.2 = the virtual space, §5.3 = the boot path, §2.1.7b = RED before green, §6's S5 row =
the specification and the gate). S0-S4 are landed (`results/x86-64-s0.md`,
`results/x86-64-s1-s2.md`, `results/x86-64-s3.md`, `results/x86-64-s4.md`); S6-S13 are untouched.

**The claim, one sentence:** a 32-bit machine can now be TOLD to be a 64-bit one
(`--long-mode on`), and when it is, it enters IA-32e through the corpus's own stub, fetches
64-bit instructions, decodes REX, executes the mov/add/push/pop/hlt/jmp subset through a
4-level page walk, and reproduces the **host CPU's** result for **12/12** of the corpus's mov
family — while the default machine is byte-for-byte the 32-bit one S4 measured.

Claims are tagged **MEASURED** (run on this host in this pass, the command or artifact named),
**READ** (from source, `file:line`) or **INTERPRETATION**. Decisions are marked as decisions.
The shipped binary's sha256 at the end of this slice is `900da5d3…` (MEASURED, `sha256sum
build/v86c`; S4 ended at `eee601d6…`), so the binary moved and every gate below ran against it.

---

## 1. The oracle, restated where it binds this slice

**The corpus IS the proof for the ISA layer, and it is the only proof there is.** Upstream v86
has no long mode at all (MEASURED in the plan: zero files under `v86/src/` match `EFER_LME`,
`EFER_LMA`, `CR4_LA57`, `PML4`; `v86/gen/x86_table.js:78` encodes `0x63` as `arpl` and
`0x40`-`0x4F` as INC/DEC). So for everything this slice lands there is **no reference in this
tree**, and the instrument is the one S4 built: a test image assembled by the host's own
assembler, executed natively by the host CPU under ptrace on one leg and by this port on the
other, with a state document compared field for field.

That has a consequence a reader must not soften: **corpus-green means "the tests we thought of
pass"**, not "long mode is correct". The 12 cases below are host-verified instruction by
instruction; the encodings they do not contain are either named stops (40 of them, §4) or not
present in the corpus at all (the census in §4 counts both). §7 lists what this slice cannot
claim.

**The 64-bit engine differential is VACUOUS at S5 — stated, not implied.** The seam can select
three engines, and exactly one of them (`interp`) declares `CPU_MODE_LONG`: `uop` and `uopjit`
refuse the mode by name (gate steps H, MEASURED). There is therefore no second engine that can
produce a long-mode state, and no document to differ against. The differential becomes a real
instrument in **S13**, where the uop decoder gets its long-mode arms and the JIT its recipes;
until then "the interpreter agrees with itself" is all a differential could say, which is why
this slice does not claim one.

## 2. The split, and the three reconciliations this report owes

### 2.1 S5a and S5b, and why the split is not bookkeeping

| | what lands | gate |
|---|---|---|
| **S5a** | the uop decoder's **long-mode refusal**; the inert state widening (`reg64[16]`, `prefixes` → `uint16_t` + REX, the REX-aware byte mapping, `CACHED_MASK_LONG` composed, the printer's sixteen slots, the poison probe seeding r8-r15, the JIT's 16-bit prefixes store); the `LMA`/`CS.L` transition; `--long-mode`; the 4 KiB 4-level walk + the 64-bit-keyed TLB; the emitter's `0x2NN` overlay whose arms ALL stop by name | `tests/gate-long-mode.sh` |
| **S5b** | the third modrm resolver (64-bit), the widened memory accessors, the REX-extended register indices in the emitted arms, `read_imm64`/`read_moffs64`, and the 62 bodies the arms call | family 1 green, case by case |

The split exists because S5a's gate has to hold **with no 64-bit body in the tree**: it is what
makes "the mode, the walk and the dispatch are real" a measurement independent of "the mov
semantics are right". MEASURED at the S5a boundary: the emitter printed `1984 call sites, 1922
implemented, 62 unimplemented; long mode: 52 routed to instr64 bodies, 62 of those call sites
unimplemented` and the corpus, with `--long-mode on`, stopped **by name** on the first 64-bit
instruction it met (`unimplemented: instructions::instr64_C7_0_reg`). That is plan §2.1.7b's
mechanical RED state, and the run reaching it at all is what proves the transition, the fetch
and the walk.

### 2.2 The count: family 1 is **12**, not "≥ 25" — the ACTUAL number is the gate

The plan's S5 row says "corpus family 1 green (≥ 25 tests)". S4's census says family 1 (`mov`) is
**12 of 57** (MEASURED: `gen/nasm64_gen.py --list`; `tests/nasm64/mov-*.asm` = 12 files). **This
slice uses the actual count and says so.** The 13 cases the projection implies would have to be
invented, and the mov encodings they could plausibly cover belong to other slices' semantics
(`0x8D` lea, `0x63` movsxd, `0x8C/0x8E` sreg moves — S7) — growing the family to hit a number
would make the gate measure the generator's arithmetic instead of the machine. The
reconciliation, in one line: **family 1 = 12/12 green; the plan's ≥ 25 was a projection made
before the corpus existed, and the corpus is the measurement.**

### 2.3 The differential is vacuous — §1, and asserted in the gate

Gate step H runs both other engines under `--long-mode on` and requires each to refuse **by
name** (`cpu backend 'uop' cannot run long mode`, `'uopjit'` likewise). A future reader who
wonders why no differential is reported here finds the reason as an assertion rather than a
silence.

## 3. What landed

### 3.1 S5a: the refusal, first

`src/cpu/uop_cache.c`, `uop_run`'s entry: `if ((cpu->efer & EFER_LMA) != 0)` → the named stop
`uop cache: the 64-bit decoder is S13's; long mode runs on the interpreter only`.

**Why it is first, and why it needs three layers.** This decoder reads the stream with 32-bit
rules: `dec_prefix` has no case for `0x40`-`0x4F`, so a REX byte is consumed as a whole
instruction and every following instruction's **length** is wrong while the stream still "runs"
— plan risk **R1**, the only silent channel that exists before any 64-bit semantics land. The
three layers are (1) the capability word, (2) S2's transition refusal, (3) this decoder-level
stop. Only (1) and (2) are reachable through the shipped dispatch today, which is exactly why
(3) has its own selftest arm (`uop_cache_selftest.c`'s `long_mode_refusal_tests`: put
`EFER.LMA` in the state by hand, require the stop; clear it, require the decoder to run).

### 3.2 S5a: the inert widening and the mode transition

- **`reg64[8]` → `reg64[16]`** (plan correction **GAP 1**). §4's inventory says `reg64[8]`, and
  S4's report read that as "r8-r15 do not exist yet, so the wide document prints zero until
  S5". They cannot arrive in eight slots: the corpus's SHARED PROLOGUE — executed by all 57
  images — zeroes `r8d`..`r15d` (`45 31 c0`-class, MEASURED), and the v2 document's sixteen
  register slots are compared against the native leg's real r8-r15.
- **`prefixes`: `uint8_t` → `uint16_t`**, REX nibble at bits 8-11 and a **PRESENT** bit at 12
  (`0x40` sets no bits and must still be distinguishable from "no REX"). `reg_index_b/_r/_x`
  extend a field index at **the one place it is formed** in the emitted code.
- **`get_reg8_index`**: index 8-15 → the first byte of the slot; **4-7 WITH a REX byte** →
  first byte (SPL/BPL/SIL/DIL); 4-7 without → the second byte (AH/CH/DH/BH). "With a REX byte"
  is `PREFIX_REX_PRESENT`, not `W` — `40 B4` is `mov spl, imm8` (MEASURED against the host).
- **The five CS-loading shapes** now carry `CS.L` (`seg_descriptor_is_long` +
  `update_cs_size_long` at all 11 sites in `exceptions.c`), and `cpu_mode_of` distinguishes
  `CPU_MODE_LONG` from `CPU_MODE_COMPAT` — the split S2's report named as the arm that could not
  exist. **This is plan correction GAP 2**, argued in §5.
- **The transition**: `EFER.LMA` set on the `CR0.PG` 0→1 edge iff LME && PAE && the backend can
  run long mode; cleared on the 1→0 edge; `reg_pdpte` invalidated on entry and `load_pdpte`
  skipped there (CR3 is a PML4 from that instant). `--long-mode on|off`, **default off**,
  declares `CPU_MODE_LONG|COMPAT` on the **interpreter only** and adopts it when no engine was
  named; a named engine that cannot run the mode is refused by name at the transition.
- **The 4 KiB 4-level walk** (`paging.c:do_page_walk64`): PML4 → PDPT → PD → PT, reusing the PAE
  body's per-entry rules (present/RW/US, the **4-level** reserved mask — bits 52-62, *not* the
  PAE mask, §6.3 —, NX, A/D), with **named stops** for a 1 GiB page, a 2 MiB page and any table
  base or page frame at/above 4 GiB (plan §5.1: truncating would turn a guest `#PF` into a
  device read). It is reached through a **parallel, 64-bit-keyed, direct-mapped TLB** (4096
  entries; `tlb_data[0x100000]` cannot key a 48-bit page) flushed from the same four entry
  points. `translate_address` and its write twin delegate their long-mode half to it.

### 3.3 S5b: the decode plumbing and the bodies

- **The three-valued key** (plan §3.6.1): `run_instruction(opcode | dispatch_os_index(opcode) <<
  8)` with 0/1/2 = 16/32/64-bit operand size, wired at **all four** call sites — `cpu.c:166`,
  `instructions.c:96` (`run_prefix_instruction`), `instructions.c:2196` (`instr_FB`),
  `uop_cache.c:1342` — plus the two selftest fakes that pin the key's shape. The plan says
  "exactly three" and lists three; **plan correction GAP 3**: `instr_FB` re-dispatches the
  opcode it fetched, so it is a fourth.
- **The overlay** `gen/x86_table64.js` (authored, 79 entries: 52 routed arms, 16 REX prefix
  cases, 2 `invalid64`, and 9 default-64 entries with no body yet) and the emitter
  `gen/interpreter_c.js`, which now emits a third arm (`case 0x2NN:`) with `size = 64` — every
  symbol renamed `instr64_*` **including the `os:false` encodings**, because `hlt` and `jmp
  rel8` have no 16/32 split and would otherwise collide with the 32-bit symbol (a name that
  exists and is wrong). An encoding **without** an entry gets a **named stop case**, which is
  not decoration: a `REX.W` byte can precede *any* opcode, and without the case the key hit the
  switch's `default: DBG_ASSERT(false)` and **aborted the host** (MEASURED: 39 of 57 cases died
  in `assert(0)` before this case existed).
- **`long_mode_default64`** is generated from the same overlay into its own translation unit
  (`src/cpu/long_mode_gen.c`) because `dispatch_os_index` needs it and the selftests do not link
  the generated dispatcher — one definition for every link.
- **`read_imm64` / `read_moffs64`** (plan §3.6.5): an immediate is 8 bytes wide in **one**
  instruction, `MOV r64, imm64` (`B8+r` with REX.W); an **moffs offset** is 8 bytes wide in long
  mode whatever the operand size is, which is why the `0x1NN` arm of `A0`-`A3` reads 8 bytes too
  (`read_moffs`, with a named stop above 4 GiB) and the `0x2NN` arms get the full 64-bit address.
- **The third resolver** `modrm_resolve64` (plan correction **W1**): RIP-relative (`mod=00
  rm=101`, base = the *next* instruction), SIB base 101 with `mod=00` → disp32 with no base,
  `REX.B`/`REX.X` extension (including **R12 as an index**, where 100b means "no index" only
  without `REX.X`), the `0x67` override computing a 32-bit address that is zero-extended, and the
  segment base added at 64 bits. Its widened partners in `paging.c` —
  `safe_read8_addr`/`safe_read64_addr`/`safe_write8_addr`/`safe_write64_addr` — exist because
  passing a 64-bit address into an `int32_t` accessor is a **wrong page with no symptom**
  (§6.2). `modrm_resolve` itself became mode-aware: in 64-bit mode it resolves at 64 bits and
  **stops by name** above 4 GiB rather than truncating, because the *no-REX.W* instructions
  (`movdqa xmm0,[rip+…]`, `push qword [mem]`) dispatch to their 32-bit arms and would otherwise
  compute RIP-relative as disp32-absolute.
- **The 62 bodies** (`src/cpu/instructions_64.c`, 401 lines): the REX handler, `mov` (0x88/89/8A/
  8B, A0-A3, B0-BF, C6/C7 /0), `add`/`xor` (0x01/03, 0x31/33), `push`/`pop` (0x50-5F), `push
  imm8/imm32` (0x6A/0x68), `pushfq`/`popfq` (0x9C/0x9D), `hlt` (0xF4) and `jmp rel8` (0xEB).

## 5. The plan corrections this slice owes (all three were found before the code, and held)

**GAP 1 — `reg64[16]` is unavoidable, and §4's inventory does not name it.** Argued in §3.2.
Consequence for S4's report: its sentence "R8-R15 do not exist in the model yet … zero until
S5" is right about S4 and wrong as a forecast — eight slots can never hold sixteen registers, so
the widening is S5's, not a later slice's.

**GAP 2 — `CS.L` and compatibility mode are S5's, not S11's.** `cpu_backend.c`'s S2 note and
§4 place the `CS.L` decode in S11 ("it arrives with the far-transfer work"). S5 cannot do "stub
→ LMA → 64-bit fetch" without it: after the stub's `mov cr0` sets `CR0.PG`, the machine **is** in
IA-32e with `CS.L = 0` — **compatibility** mode — and the very next instruction is the legacy
`.byte 0xEA` far jump that loads the 64-bit CS. Treating `LMA` as 64-bit on the instant it is
set turns that far jump into the overlay's `#UD` and **no case ever reaches its body**. MEASURED
on the way there: with the machine in compat and `is_32` true from the multiboot entry state,
the far jump decodes as `instr32_EA` (32-bit operand size, 6 bytes) — correct — and the *next*
fetch is the first 64-bit byte.

**GAP 3 — four `run_instruction` call sites, not three.** `src/cpu/instructions.c:2196`
(`instr_FB`, the `cpuid`-style hook) re-dispatches the opcode it fetched, so it carries the key.
The plan's §3.6.1 lists three.

**W1 / W2 / W3 were accepted as findings and are §3.3's design**: the third resolver plus the
widened accessors (W1), REX-extended indices at the one place the field is formed — including
the **existing** `0xNN`/`0x1NN` arms, because `45 31 c0` is `xor r8d,r8d` and reaches the 32-bit
body with an index of 8 (W2), and the two S3-era long-mode stops becoming the real walk (W3).

## 6. The six defects this slice found, each MEASURED, each fixed with its arm

**6.1 `imm64` is not a property of the 64-bit operand size** (my own first version). The first
overlay routed *every* `imm1632` to `read_imm64` at size 64, but only `B8+r` takes an 8-byte
immediate: `C7 /0` (`mov r/m64, imm32`) and `0x68` (`push imm32`) take **four bytes
sign-extended**. MEASURED: `rsp` came out `0x489d006a00102000` — the high half held the following
instruction's bytes — and 28 cases mismatched. FIX: an `imm64: true` flag on `B8`-`BF` only.

**6.2 A 64-bit body truncated into an `int32_t` accessor is a wrong page** — the silent class
W1 names. FIX: the four `safe_*_addr` accessors and `modrm_resolve64`; and §3.3's mode-aware
`modrm_resolve`, which turned four mismatching cases into *either* right answers *or* named
stops.

**6.3 The 4-level reserved mask is not the PAE one.** The PAE walk's `0x7FFFFFFF00000000` is
right for an entry whose frame is 32 bits; in a 4-level entry bits 32-51 **are** the frame, so
the reserved set is bits 52-62. Reusing the PAE mask would `#PF` on a legal frame above 4 GiB
with a reserved-bit error code — the wrong **fault**, which is its own silent class. FIX: the
4-level mask, with the ≥ 4 GiB bound answered separately and by name.

**6.4 A HOST out-of-bounds read (found by this slice's own mutation probe).** `interpreted_run`
named a fetch past guest RAM and **then indexed `mem8[phys_addr]` anyway**. MEASURED as a
**SIGSEGV of the host with no output at all** (gate mutation F2). FIX: the `return` at the
entry, the `break` at the loop tail, and the fourth conjunct in `cycle_internal`'s progress
assert (a legitimate stop must not abort the host).

**6.5 A named stop could be overwritten by its own consequence.** A walk stop aborts the
instruction through `cpu->pagefault`, and the page-fault **delivery** then raised a second stop
(`idtr_size too small for the vector`) which replaced the first — so the machine reported a
symptom. MEASURED on the 1 GiB / 2 MiB mutation probes, which found no walk stop at all. FIX:
`unimplemented_instruction` keeps the **first** name.

**6.6 A page-table read past guest RAM was another host OOB read.** `read64s` indexes `mem8`
with a `uint32_t` and has no bound, so a table base under 4 GiB but past RAM read the host's
heap. MEASURED: a mutation pointing a PDPTE at 2.2 GB in a 2 MiB machine read garbage and turned
a table error into a bare `#PF` with the wrong reason. FIX: the 4-level walk bounds every table
read by `memory_size` and names it. **The 32-bit/PAE walk above it has the same exposure and is
NOT fixed here** — it is pre-existing, reachable only with tables outside RAM, and §7 names it
for S11 rather than leaving it silent.

**And four defects in the S4 instruments, which is what the first executable run exposed** (all
named in S4's own report as the blind spot "the stub is executed by NEITHER leg"):

| | MEASURED | FIX |
|---|---|---|
| **F1 CR3 was never loaded** | the stub builds a PML4 at 0x104000 and enables paging with `CR3 = 0`, so the walk read an **empty PML4 out of physical zero**: `#PF` at `0x800b1`, the far jump's own `ea` byte | `mov eax, 0x104000 / mov cr3, eax` before `CR0.PG` |
| **F2 four-byte page-table entries** | a 4-level entry is EIGHT bytes; the fill loop wrote 4096 consecutive dwords, so each entry carried its neighbour in the high half — `PT[0x80]` read back `0x10100300100003` and the walk stopped with "physical page 0x100300100000 is above the port's 32-bit physical model" | 2048 eight-byte entries through PD[0]/PD[1] |
| **F3 the native leg inherited the parent's x87 DATA** | `fninit` sets the TAG to empty but does **not** clear the 80-bit slots, and the comparison's MMX branch fires on an all-invalid tag — so every family-1 case failed on exactly one field, `mm7.int32[1] = 0xFFFFFFFF80000000` against the model's 0, a constant unrelated to any body | FXSAVE to a scratch **above** the compared window (0x102400; a scratch at rsp-512 lands *in* the window and MEASURABLY put MXCSR at 0x101E18), zero `0x20..0x1A0`, FXRSTOR |
| **F4 the generator's census line lied** | it still said "`gen/x86_table64.js` does not exist yet (S5), so 0 encodings have an arm" | it counts the authored overlay and points at the emitter for the authoritative number |

## 7. What this slice cannot claim (so a silence is never read as a promise)

- **The corpus is the whole proof for the ISA layer**, and it is 57 cases over six families, of
  which this slice turns 12 + 5 green. An instruction the corpus does not contain is unmeasured
  even if this slice implemented it.
- **The system layer is S11's**: the full walk (1 GiB, 2 MiB, canonicality, NX composition on
  those sizes), the 64-bit TLB's page-flag split, `MOV CR*/DR*` semantics, `MSR`s, the 64-bit
  description tables and interrupt frame, `SYSCALL`/`SYSRET`/`SWAPGS`, FS/GS bases. This slice
  stops **by name** on the two page sizes and on any frame at or above 4 GiB.
- **The `0F` space has no 64-bit arms at all** (11 of the 40 red cases stop there): `SYSCALL` is
  S11's and the SSE/`cmov`/`setcc` families are S7/S10's.
- **The REX cancel rule is implemented and NOT measured by any corpus case.** `prefixes_cancel_rex`
  runs at six sites (a legacy prefix after a REX cancels it), and no case writes `48 66 …` /
  `66 48 …`. It is S6's to cover with an ALU case; until then it is code with no instrument.
- **The 64-bit engine differential is vacuous** (§1), and the JIT's long-mode coverage is zero by
  construction.
- **`is_32` in a 64-bit code segment**: `CS.D` is 0 there (the SDM requires it), so
  `is_osize_32()` answers *true* in 64-bit mode. Every 64-bit body therefore takes its operand
  size from the **dispatch key**, never from `is_osize_32()` — a rule the next slice must keep.
- **Non-canonical `#GP`** is S7's (a ring-3 load/store of `0x0000800000000000` is the host's own
  probe); the walk does not test canonicality yet.
- **The 32-bit PAE walk's unbounded table read** (§6.6) is pre-existing and S11's.

## 8. The gate, by exit code

`sh tests/gate-long-mode.sh` → **23 passed, 0 failed** (MEASURED). Steps, each an exit code:

| step | what fails it |
|---|---|
| A `off-is-32bit`, `off-refusal-names-the-reason` | with `--long-mode` off the census must be `green=0 red_unimplemented=57` **and** the stop must name `EFER.LME … 'uopjit'` |
| B `uopjit-refuses-long-mode` + its able-to-fail arm | a NAMED engine without the capability must refuse by name; the interpreter must not |
| C `uop-decoder-refusal` | the decoder's own selftest arm must pass (`PASS S5: the uop decoder refuses long mode`) |
| D `overlay-census` (79/61/23) + able-to-fail | a slice that lands arms must EDIT the number |
| E `family-1-green` (12/12), `whole-corpus-no-mismatch` (green=17 red=40 mismatch=0 error=0) + able-to-fail | counts, never a shape; the able-to-fail arm requires the assertion to refuse wrong counts |
| F five page-table mutations: PML4 absent → `#PF`; PD repointed → the fetch bound by name; `PDPTE.PS` → "a 1 GiB page … is S11"; `PDE.PS` → "a 2 MiB page … is S11"; PTE frame ≥ 4 GiB → the model bound | a walk that ignored a level passes the unmutated run and notices none of them |
| G the bound names the frame; the unmutated image has neither stop nor fault | the mutations must be distinguishable from the baseline |
| H `mode=long`, `EFER.LMA` set, and both other engines refuse by name | the mode must be the one claimed, and the differential's vacuity must be asserted |

The mutations patch the **stub's own immediates** (`tests/patch-image.py`), because the page
tables are built at runtime by the image itself; a pattern must occur **exactly once** or the
patch is an error, so a stub whose shape changed fails here instead of silently mutating nothing.

**`make nasm64` → 13 passed, 0 failed, and its census is STILL `green=0 red_unimplemented=57`
— unchanged by design**, because that gate runs the **shipped default** (`--long-mode` off). The
flag-off machine is byte-identical to S4's (step D). A reader who expects the S4 gate's numbers to
move when the bodies land has the wrong model of the slice: the capability is off by default, and
that is the requirement, not an oversight.
